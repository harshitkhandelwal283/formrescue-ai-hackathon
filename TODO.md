# FormRescue AI — Outcome Checklist

## 1. Landing page, navigation and visual system
- [x] Open to a polished, responsive, professional single-page experience for mobile and desktop. Use the requested deep midnight navy, soft off-white, refined indigo, restrained saffron/amber, green verified states and neutral grey uncertainty; generous whitespace, controlled shadows, clear readable typography, accessible contrast and touch targets.
- [x] Show the exact hero headline “Stuck on a form? Go from error to done.” and copy “Upload a confusing error or application notice. FormRescue helps you understand what went wrong, find relevant guidance and build a practical recovery plan.”
- [x] Make primary “Try a sample case” and secondary “Upload my screenshot” actions work. Include restrained error-to-checklist motion, honor reduced-motion preferences, and do not delay primary access.
- [x] Include working How it works (Understand → Verify → Recover), live diagnostic workspace, differentiation, before/after comparison, honesty/limitations, FAQ and footer. Footer includes privacy/source limitations and “Built for the Meta Global AI Developer Hackathon.” Use semantic headings/navigation and no meaningless charts or decorative clutter.

## 2. Understand workspace, screenshot input and privacy
- [~] Allow drag/drop, browse and paste where supported; preview, remove/replace, choose a demonstration case, enter error text manually, select English/Hindi, optionally choose category/jurisdiction and add context.
- [x] Accept JPG, PNG and WebP, maximum 10 MB per image; validate and show helpful messages for unsupported, oversized, unreadable, empty and failed operations.
- [x] Display the warning “Before uploading, remove passwords, one-time codes, payment-card details and personal information that is not needed for analysis.”
- [x] In demo mode, accurately state “Your sample stays in this browser. FormRescue does not upload or save it.” Uploaded images remain local and are never claimed to have been analyzed; no file/sensitive text/checklist persists across sessions. Provide a clear removal/reset action.
- [~] Provide optional rectangle redaction for uploaded images, with add/move/adjust/remove/undo, preview, clear, and solid-cover masks. Permanently flatten masks into a derived output image; never submit the original when redaction is chosen, never claim full anonymization, and do not send demo uploads anywhere.

## 3. Four fictional demonstration cases and sources
- [x] Provide four complete English/Hindi demonstrations with realistic interactive HTML/CSS fictional portal interfaces. Every portal, institution, rule, person, document and source is visibly demonstration data. Selecting a case opens its complete report immediately. Demo sources use stable internal IDs, the label “DEMO SOURCE — FICTIONAL RULE FOR THIS EXAMPLE”, and no live-looking official URL. Never describe them as live search or real authorities.
- [x] BrightPath Scholarship Portal: show “Document upload failed: file size exceeds limit.” The fictional maximum is 2 MB. Confirm the message and fictional rule; mark high-resolution scan/image-heavy PDF as likely; mark actual allowed format and real-portal rules unknown. Checklist: check size; verify actual portal format/size; make a readable appropriately sized copy if permitted; recheck/reupload; verify portal acknowledgement. Do not imply compression is always appropriate or guarantees acceptance.
- [x] Northstar Admissions Demo: show “Applicant name does not match the uploaded certificate.” Sample application/certificate strings differ. Confirm the error and differing strings; likely initials/spelling/order/spacing; unknown real matching rules or required official correction. Checklist: compare original, inspect spelling/order/initials/omissions, consult institution guidance, use permitted correction/clarification, recheck status. Never suggest falsification or unauthorized record changes.
- [x] CivicApply Demonstration Portal: show “Uploaded income certificate is older than the permitted six-month period.” Fictional scenario: issue date eight months earlier and fictional six-month window. Confirm notice/rule/date; mark rejection reason likely; actual authority rule and office/route/renewal unknown. Checklist: check date, verify actual authority, find official renewal instructions, obtain updated certificate if required/eligible, reupload and verify status.
- [x] ClearGrid Utilities Demo: show “Address proof not accepted for this connection application.” Confirm fictional message and limited fictional accepted categories; likely document category/incompleteness/unreadability/address inconsistency; unknown actual alternatives or review. Checklist: read actual provider's list, compare type, check readable/consistent fields, select a permitted proof, submit through authorized channel and verify status. Do not invent real utility rules.
- [x] Each report contains CONFIRMED / LIKELY / UNKNOWN findings with reasons, actionable checklist, possibly missing documents, questions/unverified points, fictional source cards and a verification plan.

## 4. Evidence, diagnostic report and recovery checklist
- [x] Use text labels and icons as well as green/amber/grey, never color alone. Explain what is visible in a screenshot separately from official rules. Never promote a plausible explanation to confirmed merely because the AI sounds certain.
- [x] Findings show statement, status, reason, source when relevant and what additional information would resolve uncertainty. Real official-rule claims require actual supporting sources; when retrieval is unavailable, say so and keep them unverified. Never fabricate citations, URLs, official quotes, dates or retrieval timestamps.
- [x] Provide an evidence-strength/coverage indicator based on a documented coverage rubric, state that it is indicative and not a statistically validated probability, and communicate remaining uncertainty. A high indicator must not override missing/contradictory evidence.
- [x] Provide recover steps with action title, explanation, checkbox, why it may help, relevant source where available, non-guaranteed duration only if reasonable, prerequisite and success verification. Include missing documents, questions, unverified matters, how to verify correction, and what to do if the next attempt fails.
- [x] Checklist progress remains in memory for the current session. Support marking complete, copying plan, printing the report, starting a new analysis and feedback on whether a correction worked.

## 6. Live AI mode, sources and safe behavior
- [x] Default to offline DEMO MODE; the four cases work without API key, account, backend or external networks. An uploaded demo image only previews locally; disclose that genuine analysis is unavailable.
- [x] Provide an optional Live AI mode/configuration UI with selected provider/status and a way back to demo. Do not invent provider endpoints, auth formats, model IDs or capabilities. If no provider is configured, make that explicit and document exactly what is missing; no fake connection test, AI report, OCR finding or live citation.
- [x] Never persist credentials or user documents. If any browser-only provider/key behavior is implemented, keep it only in runtime memory, use only documented browser-supported vision APIs, warn client-side keys are inspectable/not safe for public deployment, and never place them in local/session storage, URLs, source, analytics or logs. Prefer server-side credentials for public use.
- [~] A future live pipeline must validate file, apply chosen redaction, send only permitted content/context, validate returned structure, separate evidence/uncertainty, and handle malformed, unreadable, unsupported-language, contradictory, network and model errors. Failed live analysis must not become a fictional success; switching to demo must say the failed live request produced no valid analysis and the demo is fictional/not based on the image.
- [x] Treat screenshot text as untrusted input. Do not make unsupported claims about eligibility, identity, outcome, official status or legal rights. Never ask for passwords or one-time codes. Clearly state the app cannot submit applications, guarantee acceptance, reverse official rejections, replace an authority/helpline, or determine facts absent from evidence; direct users to officials for uncertain deadlines, rejections, eligibility or document rules.
